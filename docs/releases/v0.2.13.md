# v0.2.13 — Bounded Task Routing Validation

This release retains the complete v0.2.12 bounded plan–act–verify task loop and
corrects a production-live semantic-routing defect found during final WP3
verification.

The request-understanding layer now treats create/make/add action polarity as
authoritative when a non-existent local path is the target. Asking to preview
creation therefore selects the registered `filesystem.create_directory`
mutation and its exact approval boundary; the word “preview” cannot turn the
request into a read of a file that does not exist. The rule is semantic and
path-independent, with transformed production `/chat` regression coverage.

All v0.2.12 authority, persistence, verification, recovery, UI, and explicit
WP4/WP5 exclusions remain unchanged.
