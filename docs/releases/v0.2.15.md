# v0.2.15 — Safe Pack Capability Runtime

This release adds Work Package 4 on top of the completed v0.2.14 task loop.
Explicitly supplied local packs now have three distinct classes: non-executable
portable text, strict declarative capabilities, and sandboxed pure-computation
WebAssembly capabilities.

Usable external capabilities are exact digest-bound `pack.*` entries in the
same live registry used by native chat and durable tasks. Import, review,
permissions, enablement and use remain separate one-use confirmation gates.
Updates, revocation, corruption and isolation failure remove authority without
substituting versions.

Executable modules never enter the API process. Each invocation runs in a
short-lived Bubblewrap namespace and a no-WASI, no-import Wasmtime store with
fuel, memory, wall-time and output ceilings. Host filesystem, network, DNS,
environment, secrets, database, service control and child processes are absent.

The canonical release gate adds commit-bound WP4 contract, lifecycle, dynamic
registry, `/chat`, WP3 composition, revocation, timeout, redaction and actual
worker-isolation proof. No automatic acquisition or assistant-created-pack
behavior is included; those remain WP5.

Dependency audit note: Python dependencies are consistent. The locked Web UI
retains the previously accepted one high Vite development-server advisory and
one moderate transitive esbuild development-server advisory. The promoted
runtime serves only static built assets and does not run the Vite development
server; the available fix is a semver-major Vite rewrite outside WP4.
