# Personal Agent v0.2.21

This Work Package 5 release adds safe, useful external-pack acquisition above
the existing WP1–WP4.5 authorities. It does not add a second router, registry,
task loop, or approval path.

- Read-only missing-capability discovery can inspect enabled configured catalog
  metadata. It never fetches automatically.
- Exact-confirmed GitHub and generic HTTPS archives go only to quarantine via a
  direct certificate/DNS/peer-validated transport and hostile archive intake.
- Remote and assistant-created candidates start unapproved, disabled,
  unpermissioned, inactive, and unregistered.
- Declarative packs can use core-owned selected-file/private-index, pack-private
  structured storage, exact public HTTPS GET/HEAD, and validated PNG presence
  visualizer contracts. Private local data cannot flow to the network broker.
- Exact versions support bounded comparison, atomic activation, rollback,
  immediate disable/revocation, and private-data retain/delete removal choices.
- Dynamic capabilities still enter only the live `CapabilityRegistry`, and WP3
  completion still requires registry and task-level verifier evidence.

Arbitrary Python, JavaScript, shell, native dependencies, broad filesystem or
network access, browser/OAuth integrations, pack-visible secrets, pack UI code,
and automatic fetch/approval/grant/enable/update/use remain unsupported.

WP5 preserves the user-approved default `ollama:qwen2.5:3b-instruct`, Safe Mode,
disabled remote model fallback, installed model artifacts, and live pack state.
